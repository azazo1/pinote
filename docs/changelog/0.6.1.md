# Pinote v0.6.1

Date: 2026-09-11

本版本修复 macOS 上自动更新始终失败的问题, 并让下载过程中的取消按钮真正可用. 如果你正在 macOS 上使用 v0.6.0, 请先阅读 Upgrade Notes 再升级.

## Highlights

- macOS: 自动更新不再在替换应用包时失败. 修复前暂存与备份目录被算到了应用包所在目录的上一层, 也就是只读的系统根卷, 复制新版本这一步必然报错并回退到旧版本.
- 更新替换的暂存与备份目录现在始终与应用包同级, 并在动手替换前先校验目录形状, 不会因为路径算错而波及同级目录.
- 下载过程中可以正常点击 "取消更新", 之前下载会占住界面调用, 取消请求无法送达.

## Upgrade Notes

1. v0.6.0 在 macOS 上的自动更新是失效的, 而替换脚本由正在运行的旧版本自己生成, 所以无法靠应用内更新升到本版本. 需要手动下载 `pinote-0.6.1-macos-aarch64.dmg` (Intel 机器使用 `pinote-0.6.1-macos-x86_64.dmg`), 把其中的应用拖入 "应用程序" 覆盖安装一次.
2. 覆盖安装不会影响便签数据, 设置与同步配置, 它们保存在数据目录中, 与安装方式无关.
3. 从本版本开始, 后续版本可以正常通过应用内更新升级.
4. 在 macOS 上安装了 v0.6.0 之后又回退过版本的用户, 数据目录中可能残留下载好的安装包和替换日志, 它们不影响使用, 可以自行清理.

## Bug Fixes

- macOS 自动更新: 暂存目录与备份目录改为从应用包本身推导, 不再退到应用包所在目录的上一层. 修复前它们会落到系统根卷上的 `/.Pinote.app.update-<version>` 与 `/Applications.old`, 每次替换都以 "复制新版本失败, 请手动安装." 告终.
- macOS 自动更新: 替换脚本在改名和删除之前先校验两个路径确实与应用包同级, 不符合预期时直接中止并落盘原因, 不触碰任何路径; 失败回滚也只撤销确实执行过的动作.
- macOS 与 Windows 自动更新: 替换脚本以及 `hdiutil`, `ditto`, `mv` 等外部命令的输出写入 `apply-update.log`, 排查失败时可以看到具体原因, 而不是只有一句笼统的提示.
- 更新下载: "取消更新" 按钮在下载期间恢复可用, 取消后回到可以重新发起的状态.
- 启动清理: 更新遗留的备份与暂存目录按新的路径规则清理, macOS 上此前实际上从未清理到这些目录.
